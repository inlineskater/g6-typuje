# Ogródek / Farma — frontend UI conventions

Cross-cutting frontend/UX conventions for the farm hub UI (hub-modal layout, card design, nav-bar behavior). This is NOT the gameplay/economy doc — for how the farm economy itself works (tiles, lootboxes, NFTs, pricing, land tax, marketplace), see `docs/farma.md`. CLAUDE.md keeps a short summary of the points below; this is the full detail.

### Ogródek / nav UI conventions (2026-07-25)

- **One crop card per `crop_type`, not per plant.** Every weekly NFT edition and every bred hybrid harvests into the shared `seasonal_bloom` crop backed by ONE `farm_market` row, so the 📈 Cennik tab groups defs through `farmCropGroups()` and labels shared crops from `FARM_SHARED_CROP_LABELS` („Kwiat sezonowy"), listing the contributing plants underneath. Rendering a card per plant printed the identical price/chart ~19 times and read as a bug. Differentiation between those plants lives in `base_yield`/`base_grow_minutes`, not in price.
- **Never name a crop pile with `[...fmDefs.values()].find(d => d.crop_type === ct)` — use `farmCropIdentity(ct)`** (2026-08-04). Any code that starts from a `crop_type` (inventory rows, the sell dialog, the global sales log) used to label the pile with the *first def that happened to match*, which for `seasonal_bloom` printed one arbitrary name out of the 12 active defs — routinely a plant the player doesn't own (a real report showed „Kryształowa Peonia ×474" to a player whose 474 units came from two `wild_hybrid` instances; `crystal_peony.minted_count` was 0). Combined with `harvest_crop` writing **one `farm_inventory` lot per harvest but the UI summing lots per `crop_type`**, two harvests from two different NFTs read as „I harvested 2 NFTs and only 1 showed up, and it's priced as the cheaper one". `farmCropIdentity()` returns `{name, emoji, defs, shared, note}` using the same „>1 def ⇒ `FARM_SHARED_CROP_LABELS`" rule as `farmCropGroups()`, so pooled piles are „🌸 Kwiat sezonowy" everywhere. **Lots carry no species column**, so per-NFT attribution is impossible after harvest — the honest fix is naming the pool and saying what pooling means: a `🧬 wspólny plon N roślin` chip on the Mój Majątek row (tooltip lists the contributing plants) and a note in the sell dialog, both spelling out that **a better card yields MORE units, not pricier units**.
- **An NFT egzemplarz is drawn with `farmNftEmoji(n)` / `farmNftIconFor(species, serial, speciesEmoji)`, never with `def.emoji`** (2026-08-07). Icons live on `farm_card_defs`, i.e. per SPECIES — fine for a nakład of 8, wrong for `wild_hybrid`, the catch-all every uncatalogued parent pair collapses onto. Its nakład of 500 meant one 🌈 stood in for every wild hybrid ever bred, so a collection, the edition grid, Targowisko and the field all rendered a wall of identical rainbows over cards that share no stats at all (each carries parent-derived `stat_yield`/`stat_grow_minutes`/`stat_value`). Each serial now maps into `WILD_HYBRID_ICONS` (28 crop/plant emoji) by `(serial - 1) % length` — the same deterministic-from-serial trick as `farmNftFlavor()`, so **no server column and no migration**: every player sees the same icon for #7, offline or not. ⚠️ **`WILD_HYBRID_ICONS` is append-only** — reordering or removing an entry re-skins cards people already own. Curated recipes keep their own emoji (they ARE a species: 🌹 Słoneczna Róża); only the wild catch-all varies, and surfaces that render a *species* rather than an egzemplarz (the Katalog row's leading icon, the explorer header, the box-odds table, the Top-5 aggregates) correctly stay 🌈. Three call sites need the indirection because they hold no instance row: `farmListingEmoji(listing)` resolves a Targowisko listing through `fmNft` by `nft_instance_id` (the listing froze the species emoji at creation and `marketplace_cards` exposes no species column), `farmTileCropEmoji(tile)` resolves a planted card through `planted_instance_id` (and is what `farmCropStageIcon`/`applyFarmCropVisual` now take — they take a ripe-stage EMOJI, not a def), and the hybrid feed/transfer log pass `(species, serial)` straight to `farmNftIconFor`. The breeding preview deliberately keeps 🌈: the serial isn't assigned until `breed_nft` commits, so it names the rule („własna ikona dla numeru") instead of guessing a variety it might not deliver.
- **Clicking an NFT row in 📖 Katalog opens `openFarmNftExplorer` — the single source of truth for that card.** For normal NFT editions it carries the stats block, the per-level ladder (`farmCardLevelTable(def, price, level, { nft: true })` — merge-worded costs), every serial slot, and the ownership/price history. **Bred hybrids are deliberately different:** every instance stores parent-derived `stat_yield`/`stat_grow_minutes`/`stat_value`, so the catalog must not print one species-level profit ladder or advertise one owned level for the whole row. A hybrid row says that its profit is individual (or sums the real instance stats when the viewer has that hybrid planted), ownership shows serials without `Lvl`, and the explorer routes exact stats to 🎒 Mój Majątek. The old „Pokaż wszystkie" button that opened a second modal is gone; fungible cards still open `openFarmLevelModal`.
- **Clicking an NFT in 🎒 Mój Majątek opens `openFarmNftModal` — the owned-instance sheet, the counterpart to the catalog's `openFarmNftExplorer` (which is about the *edition*).** Below the trading card it carries `farmNftIncomeBlock` (the headline **Zysk/doba as a RANGE**, plus a meter marking where today's NPC price sits inside the 30–100%-of-pułap band, the „dziś" figure, the weekly-contract premium, and the Renoma Kolekcjonera uplift) and `farmNftStatSheet` (yield/grow/harvests-per-week/crop, the live vs ceiling price, per-harvest and per-day earnings, serial, level, net-worth value, where the card physically is — planted on działka [x,y] / listed / in the collection — and what the next merge level would change plus its cost). **Every income figure is a range on purpose**: the anchor re-rolls to 30–100% of the catalog max twice daily, so a single number would always be wrong in one direction. The math is `farmPlantIncomeCalc(def, level, over)` — the same helper the plant picker uses — with `over` supplying the instance's effective stats via `farmNftIncomeCalc`/`farmNftStatsAtLevel`, because a **bred hybrid carries its own `stat_yield`/`stat_grow_minutes`** and deriving from the species def would misprice it. Do not route this through `farmNftStats().perDay`: that one is the byte-for-byte mirror of `farm_hybrid_stats()` used by the breeding preview and must keep using `base_price` unmodified. The collector bonus is shown as a separate labelled line rather than folded into the headline, so the range stays comparable with the catalog and the plant picker.
- **🌟 Co zasadzić (`majPlantAdvisor`) sits right under 🧺 Plony in Mój Majątek** — the short answer to „which of my cards deserves the tile?". `farmPlantableRanking()` merges fungible cards and NFT egzemplarze into ONE ranking (a level-12 Kukurydza legitimately beats a level-1 NFT) and keeps only what is free to plant right now, mirroring the plant picker's eligibility rules: a fungible card at level 2+ is an unlimited seed, level 1 is capped by copies not already in the ground, and an NFT is one planting per unlisted, unplanted instance. Sorted by `calc.dayHigh` (the top of the 30–100% price band = „najwyższy możliwy zarobek"), ties broken on today's price then the shorter grow time. `MAJ_ADVISOR_TOP_N` is **6** on purpose — this is a nudge above the collection, not a second catalog; the header count is what's on screen and the footnote names the leftovers. **A row carrying an active weekly-contract premium must stay flagged** (`🏆 kontrakt +N/szt` + a gold tint): the premium lifts BOTH ends of the range — on the 2026-07-29 board it doubled Kukurydza's ceiling from a base of 16 — so an unmarked row reads as a permanently better card and stops being one the moment the week ends.
- **The empty-tile plant picker keeps its catalog-style order by default and offers `Najbardziej opłacalne` as an explicit sort mode.** Profit sorting uses the same `farmDailyProfitCompare()` rule as `majPlantAdvisor` (`dayHigh` → `dayNow` → shorter growth), so the two surfaces agree. It ranks plantable, priced cards first; plantable cards without a market price follow; unavailable cards remain last in their original order. The choice is local to the open picker and is not persisted.
- `farmTaxStatusCard()` and `buildFarmSeasonalBody()` follow the same shape: status pill → one plain-language lead sentence → the numbers → detail in `<details>` or a numbered block. Neither hardcodes dates any more (the tax note used to quote a fixed 03.07.2026).
- **One frame per screen.** `.farm-hub-body` is the hub's only outline; everything inside it separates with spacing, a single hairline, or a flat tint — never its own border. That is why `.maj-crop-card`, `.deed-chip`, `.farm-tax-card`, `.farm-seasonal-goal`, `.farm-seasonal-prize`, `.farm-ach-card` and `.nftx-fact` are borderless. Font weights top out at 700, and a colour wash is reserved for states you can act on (unpaid tax debt), not for every notable state. Don't reintroduce boxes-inside-boxes.
- `plCount(n, one, few, many)` handles Polish 1 / 2-4 / 5+ plurals — use it for any counted noun.
- **Wood is scenery only** (`.notice-board`, `.plot-sign`, `.farm-divider`). Chrome that carries controls — `.farm-topbar`, hub modals, panels — uses the neutral `--r-*`/`--sh-*` tokens.
- `.nav-tabs` are pill targets with an `--acc-dim` active state, **sticky at every width** (2026-07-26). The offset can't be a constant — the mobile header wraps to two rows (87px vs the desktop 58px) — so `syncNavOffset()` measures the header and the nav with a `ResizeObserver` and publishes `--nav-top`/`--nav-h`; anything that sticks below the nav (`.shop-category-filters`, the mobile dropdown's `max-height`) is expressed in terms of them. The measurement is skipped while `#screen-app` is `display:none` (pre-login), so the CSS fallbacks hold until the observer fires on the 0 → visible transition. **Being positioned is also what keeps the dropdowns clickable**: `.nav-tabs` has a `backdrop-filter`, which creates a stacking context, so while it was static (the old mobile behaviour) its `z-index: 200` dropdowns were trapped inside it and painted *below* every `position: relative` card on the page — the Ogródek covered the „Gry" menu. The chrome stack is now page popovers (`.gp-details-popover`, `.ftbl-menu`) 30 < `.nav-tabs` 40 < `header` 41 < modals/toasts 100+. The mobile bar wraps rather than scrolling horizontally — the dropdowns are absolutely positioned children and an `overflow-x` container would clip them — with content-sized centered pills (flex-grow made „Ogródek" balloon to half the bar), and under 761px `.nav-group` goes `position: static` so each menu is one full-width scrollable sheet under the bar instead of a narrow popup hanging off whichever wrapped pill was tapped.
