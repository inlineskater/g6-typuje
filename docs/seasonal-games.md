# Seasonal games — per-game deep dives

Full mechanic descriptions, tuning history, and parity-contract detail for each seasonal arcade game. CLAUDE.md keeps a condensed one-paragraph summary per game plus the shared stack shape; this doc has the rest.

Bug Jumper relaunched 2026-07-27 with a **dynamic course** (`course_id = 'bug_jumper_dynamic_v1'`, `supabase/bug-jumper-dynamic-course.sql` — run after `supabase/bug-jumper.sql`, supersedes its `course_id = 'bug_jumper_hard_v2'` views/award function the same way the earlier `bug_jumper_hard_v2` relaunch superseded `legacy_random_v1`): each round draws a random `seed` (new `bug_jumper_rounds.seed` column, same deterministic-seed pattern as Snake/Invoice Horde/Popup Panic) and both the browser and `bug-jumper-action` derive an identical 10-column, 30-line course from it via `bjGenerateCourse`/`generateCourse` — a random **corridor shape** per round (straight, L-turn, S-curve, or zigzag, picked from `BJ_SHAPES`) walls off part of every non-safe line, so climbing isn't pure "always jump up": the player must shuffle sideways to stay inside the shifting band before advancing a row. Safe rest lines stay at 10/20/30 (always fully open), one point per line reached, server replay of the submitted movement log, `completion_ms` tie-breaks, and dynamic-course-only leaderboard/award views. Older rows remain stored as `legacy_random_v1` then `bug_jumper_hard_v2`. `scripts/bj-parity.mjs` fuzzes course generation + randomly-driven move logs through both transcribed copies and asserts 0 mismatches whenever `bjGenerateCourse`/`bjCellBlocked`/`bjCellOpen` (index.html) or `generateCourse`/`cellBlocked`/`cellOpen` (`bug-jumper-action`) change.

`supabase/bug-jumper-top5-scoring.sql` (run after `bug-jumper-dynamic-course.sql`) changed how rounds aggregate into a rank: `bug_jumper_current_week`/`bug_jumper_all_time`/`award_bug_jumper_week` now average each player's **top 5 scoring rounds** (fewer than 5 played just averages over however many exist) instead of taking their single best round — rewards a consistently good run of attempts without requiring endless grinding, since extra rounds outside your best 5 don't move the average. The per-round score itself is unchanged (0-30). The weekly award row still stores an integer (`ROUND(avg_score)`) for schema compatibility, but the live views expose the precise `numeric` average. `hits`/`misses`/`max_combo`/`base_score`/`item_bonus` were dropped from the two leaderboard views since they don't have one sensible value once 5 rounds are averaged.

Bug Jumper wide-board redesign (2026-07, no SQL — index.html + `bug-jumper-action` only, `COURSE_VERSION` bumped to 5, supersedes the brief route-picker/`BJ_SHAPES` iteration that preceded it): the board is now **56 cols × 32 rows** (was 10×32) — a ~16:9 board sized to fit a fullscreen monitor rather than a narrow phone-shaped strip — with the corridor **always fully dynamic**: instead of picking one of a few fixed L/S/zigzag templates, `bjGenerateCourse`/`generateCourse` walks the corridor's center by a random ±`BJ_DRIFT_MAX` (3) columns **every row** (`BJ_BAND_HALF` 7, band 15 of 56 cols), so no two rounds ever look alike and there's nothing left to pick from — the pre-round route picker from the previous iteration is gone (client and server both dropped `BJ_SHAPES`/`shapeIndex`/the `#bj-shape-row` UI entirely). Each non-safe line now rolls 1-3 obstacles from **three kinds**: `crawl` (the original bug — sweeps the band and wraps at the edges), `bounce` (paces back and forth inside a smaller sub-range, never wraps — rendered as ☎️), and `block` (stationary, rendered as 🚧; unlike crawl it doesn't wrap, so its `col` roll is clamped to `bandWidth - len + 1` to keep it fully inside the band). `firstCollisionBetween`'s server-side replay sampling changed from stepping by one lane-wide interval to `nextLaneStepAfter` scanning the soonest next state-change across all of a lane's obstacles (block obstacles never contribute a step). The color theme moved off neon-green Matrix styling to a cyan/rose/amber dark-IDE palette (`.bj-arena` border/glow, wall fill, grid lines, sprites, idle overlay). A real **Fullscreen API** toggle (`#bj-fullscreen-btn`, `.bj-game-panel:fullscreen`/`:-webkit-full-screen` CSS) fills the viewport and hides the rules/prizes/subtitle chatter, `fullscreenchange`/`webkitfullscreenchange` re-run `bjInitCanvas`/`bjDraw` to match the new size. `scripts/bj-parity.mjs` was rewritten for the new generator (0 course/replay mismatches across 400+ seeds) and gained sanity checks — including simulating `crawl`'s wrap at multiple timestamps to confirm every rendered segment stays in-band, which caught the `block` clamp bug above during development.

„3 Pary Spodni" (Flappy Pants) is a Flappy Bird clone: you ARE a pair of trousers (Space/click/↑ to flap) with 3 lives (the "3 pary spodni"); each crash costs one pair with brief invincibility, and the round ends after the third. Score = obstacles passed; it persists across lives.

Snake is a 20x20 seeded-grid seasonal game prompted by Filip with `do snake, make no mistakes`. The browser submits direction changes, and `snake-action` replays them server-side to determine apples eaten before wall/self collision or the 120-second cap. Weekly ranking uses score descending, then shorter `duration_ms`, then earlier submission.

„Najazd Ticketów" (internal gameType `invoice_horde`) is an original IT-helpdesk arena-survivor (inspired by the Vampire-Survivors / Devil-Daggers genre, written from scratch — not copied). You run an IT guy 🧑‍💻 (8-way WASD/arrows/swipe) dodging an endless swarm of support tickets 🎫 that home in from the edges; an auto-firing „ROZWIĄZANE" script hitscans the nearest ticket in range (+1 resolved). Every ~125 ticks (~10 s) a **„CF" mini-boss** spawns — an oversized, slower (`BOSS_SPEED = 4`), bigger-hitbox ticket that soaks `BOSS_HP = 5` script hits before dying for `BOSS_SCORE = 5`; it lives in the same `enemies` array flagged `boss:true`, so focusing it lets the swarm pile up (risk/reward). Its 👔/"CF"/HP-bar rendering is client-only cosmetic; its constants are part of the byte-for-byte parity contract. **Survival mode, one life:** a single touch ends the run — there is no countdown, the spawn rate ramps until it outpaces the script so standing still gets you surrounded (you must kite the swarm into a trailing line). `ROUND_DURATION_MS` (60 s) is only a hard replay/safety cap; the swarm is capped at `ENEMY_CAP = 70`. Like Snake it is a **deterministic integer simulation on an 80 ms tick** (seeded LCG enemy spawns, `isqrt`-based homing, no floats that desync) — the browser logs only input-direction changes `{tick,dir}`, and `invoice-horde-action` replays `seed + moves` to derive the trusted kill count (anti-cheat ceiling `MAX_SCORE_PER_ROUND = 200`). The client renders at 60 fps by interpolating between sim ticks, with canvas particle/`+1`/death-shake effects that are purely cosmetic (never read by the sim or submitted). Weekly ranking: score (tickets resolved) descending, then **longer** `duration_ms` (survival time), then earlier submission. The constant block in `index.html` (IH_*) and `invoice-horde-action` must stay byte-for-byte equivalent — there is a headless parity harness pattern (client tick-sim vs server replay) used to verify 0 mismatches whenever they change.

VAR Patrol (internal gameType `var_patrol`) is a rapid football-officiating judgement game. The Edge Function issues a server-owned schedule of offside/foul/handball/goalline scenarios, strips the authoritative answer before returning it, and validates submitted `{index, answer, reactionMs}` decisions against the schedule with a 120 ms reaction floor and shrinking decision window. The browser renders the visible scene and two verdict buttons; local score/accuracy/combo are cosmetic, while `var-patrol-action` stores the trusted score and leaderboards. Weekly ranking uses score descending, accuracy descending, then earlier submission.

„Łap Jajka" (internal gameType `egg_catch`) is a Nu-pogodi/„Elektronika"-style LCD egg catcher: eggs roll down 4 chutes from hens at the top, and a wolf 🐺 catches them by moving between 4 basket positions (Q/A/P/L, arrow keys, or tapping a screen quadrant); 3 broken eggs (missed catches) end the run, and speed ramps up every 10 eggs spawned (`EC_LEVEL_EVERY`). Like Snake/Invoice Horde it is a **deterministic integer simulation on a 100 ms tick** (seeded LCG spawns via `ecRng`/`ecAdvanceTick`) — the browser logs only wolf-position changes `{tick,pos}`, and `egg-catch-action` replays `seed + moves` to derive the trusted catch count (anti-cheat ceiling `EC_MAX_SCORE = 1000`, `EC_MAX_TICKS = 6000` = 10 min hard cap). The constant block in `index.html` (`EC_*`) and `egg-catch-action` must stay byte-for-byte equivalent for the simulation transition functions (rendering-only constants like `EC_CS_W`/`EC_MAX_DPR` are client-only). Weekly ranking uses score descending, then earlier submission.

„Super Mariusz" (internal gameType `super_mariusz`) is a Mario-style HARDMODE **one-life** speedrun platformer on a fixed shared office-corridor course (`SM_COURSE`, `course_id = 'super_mariusz_v2'` — no per-round randomness). Touching a spike, a patrolling enemy 💼, or falling into a pit kills instantly; ranking is **progress first, time second** (2026-07-10 change — most players never finish, so distance must count). The stored `score` is the **progress in tile columns** reached by the player's center (`smProgressScore`: peak `maxX`, capped at the flag column = 455), so the existing `ORDER BY score DESC, completion_ms ASC NULLS LAST` machinery ranks distance first; every finisher scores exactly 455 and competes on `completion_ms ASC` (`smFormatTime()` renders it as `m:ss.cs`, shown with a 🏁 prefix), while DNF rows display the progress percent (`smProgressPct`). A death or hitting the 5-minute cap (`SM_MAX_TICKS = 6000`) is a **DNF**: `completed = false`, `completion_ms = NULL`, but the progress score still counts and DNFs CAN win weekly awards (`award_super_mariusz_week` filters `score > 0`, which any run satisfies — the start column already scores 2). Like Snake/Invoice Horde/Łap Jajka it is a **deterministic integer simulation on a 50 ms tick** (fixed-point physics, 256 sub-units/tile, no floats) — the browser logs only held-key bitmask changes `{tick,keys}` (bit0 LEFT, bit1 RIGHT, bit2 JUMP) via `smAdvanceTick`, and `super-mariusz-action` replays the course + moves to derive the trusted result (anti-cheat: submitted `elapsedTicks` capped against wall-clock elapsed +1.5s tolerance). Hero `score_bonus` items apply as a **time bonus, not points** (2026-07-13, per Kornel's request): progress can't be boosted (it would credit tiles never reached), so `super-mariusz-action` subtracts `SM_ITEM_TIME_BONUS_MS_PER_POINT` (400 ms) × `effect_value` from a **FINISHED** run's `completion_ms` (e.g. `kaiser_helm` +5 → −2.0 s; DNFs unaffected), recording `item_effect` (`bonus_ms`, `base_completion_ms`) in `client_meta`; the cross-game `getStrongestHeroEffect` list in that function includes `egg_catch`+`super_mariusz` and filters `expires_at`. **`super_mariusz_v2` (2026-07-09) is a brutal ~460-column, ~66s-optimal-clean-run course** — spike gauntlets, 4-5 tile max-distance pit jumps, a floating-platform section over a bottomless pit, patrolling-enemy ledges (`SM_ENEMY_SPEED` raised 24→32), a 2-row ceiling squeeze, and a final combined gauntlet — replacing the original `super_mariusz_v1` test course (27s clean run, too easy). The `SM_*` constant block, `SM_COURSE`, and the `smParseCourse`/`smInitState`/`smAdvanceTick`/`smProgressScore` transition functions in `index.html` and `super-mariusz-action` must stay byte-for-byte equivalent (rendering-only constants like `SM_CS_W`/`SM_TILE_PX` are client-only); `scripts/sm-parity.mjs` fuzzes both copies against a golden completable run and course-geometry sanity checks. **`scripts/sm-solve.mjs`** is a beam-search solver (states keyed by `tick/x/y/vx/vy/onGround`, scored by x-progress) used to find/verify a completing `GOLDEN_MOVES` log whenever the course changes — run it after any course edit and paste the resulting move log + endTick/completionMs into `sm-parity.mjs`'s golden-run assertion (must land in the 60-90s band). The rendering is full NES/SMB1-pixel-art (`smDraw`/`smInitCanvas` in `index.html`, `imageSmoothingEnabled = false`, 8×8 virtual-pixel sprites for tiles/spikes/player/enemies/flag, deterministic parallax clouds/bushes, a scanline overlay, and `Press Start 2P` HUD font on the SM stat/status text) — purely client-only, no sound. Weekly ranking uses score descending (progress), then `completion_ms` ascending among finishers, then earlier submission.

„Zamknij Popupy!" (internal gameType `popup_panic`) is a fast **~30-second, one-run** popup-closing frenzy (debuts via override on the week starting 2026-07-20). Random error/spam/malware popups pile onto a fake office desktop; you click/tap each to close it. **Two lose conditions:** `PP_MAX_OPEN` (12) popups open **at once** = buried, and a red **malware** popup left open past its `PP_MALWARE_TICKS` (25-tick / 2.5 s) deadline = infected. Surviving to `PP_ROUND_TICKS` (300 ticks) wins. Score is weighted: normal popup `PP_SCORE_NORMAL` (+1), malware `PP_SCORE_MALWARE` (+3). Spawns ramp (`ppSpawnGap` shrinks from `PP_SPAWN_GAP_START` 8 to `PP_SPAWN_GAP_MIN` 2 every `PP_RAMP_EVERY` 30 ticks) and can come in 2-popup bursts after tick 120. Like Snake/Invoice Horde/Łap Jajka it is a **deterministic integer simulation on a 100 ms tick** (seeded LCG spawns via `ppRng`/`ppSpawnOne`) — the browser logs only the popup **ids it closed per tick** `{tick,id}`, and `popup-panic-action` replays `seed + events` to derive the trusted score (a close is only credited if that id was actually open and had materialized ≥`PP_MIN_REACTION_TICKS` after spawn). Anti-cheat ceilings: `PP_MAX_SCORE` 2000, `PP_MAX_EVENTS` 3000; `elapsedTicks` capped against wall-clock elapsed +1.5 s. Hero `score_bonus` items apply as a flat point bonus (the cross-game `getStrongestHeroEffect` list in that function includes `egg_catch`+`super_mariusz`+`popup_panic` and filters `i.expires_at`). The `PP_*` constant block and the `ppInitState`/`ppRng`/`ppSpawnGap`/`ppSpawnOne`/`ppAdvanceTick` transition functions in `index.html` and `popup-panic-action` must stay byte-for-byte equivalent (cosmetic constants — `PP_NORMAL_POPUPS`/`PP_MALWARE_POPUPS` message pools, board-position rendering — are client-only, derived from popup id, NOT the shared RNG); `scripts/pp-parity.mjs` fuzzes a realistic player-driver's event logs (greedy/malware-only/random/slow/none strategies, plus garbage-id injection) through both transcribed copies and asserts 0 mismatches across all three outcomes. Rendering is **DOM-based** (authentic Win95/XP-style popup windows with title bars, red ✕, and a draining deadline bar on malware; `pp-*` CSS classes on a `#pp-arena` fake desktop with a faux taskbar) — no canvas. Weekly ranking uses score descending, then earlier submission (`accuracy` stores survival %). Run order: `popup-panic.sql`, then re-run `season-award-gating.sql`.

„Kulki G6" (internal gameType `bubble_breaker`) is **Bubble Breaker / SameGame**, the Windows Mobile puzzle that shipped on every Pocket PC — promoted from arcade-only to a full seasonal game on **2026-08-05** and debuting via override on the week starting **2026-08-10** (it took the slot Filler had been given). A 15×15 board of 5-colour balls; tap a group of touching same-colour balls to pop it, balls fall into the gap, empty columns slide left, and the round ends when no pair is left. Score is **n×(n−1) per group** (`BB_CLEAR_BONUS` +1000 for emptying the board), deliberately superlinear so one group of 10 (90) beats five groups of 2 (10) — patience is the skill, not speed. `scripts/bb-parity.mjs` measures a greedy bot at **~570 average, ~1300 peak** over a few thousand seeds, and no policy has ever cleared a board.

**It is the odd one out in the rotation twice over.** First, there is **no tick clock and no per-tick input**: a round is fully described by `(seed, [tapped cell indices])`, which makes it the cheapest replay of any seasonal game — `bubble-breaker-action`'s `submit` just walks the list through `bbPopAt` and every tap must be a legal pop (a fabricated group, an empty cell, or a single ball aborts the whole submission with `Niepoprawny ruch w zapisie rundy`). A round is only scoreable once `st.over` is true, i.e. no pair remains; bailing out early is allowed but not submittable, otherwise the optimal strategy would be to stop the instant the score peaks. Second, and because of the first, it is the one game where an **offline solver over the server-issued seed is cheap** — the sim would happily accept 60 optimal pops submitted in the same millisecond. Wall-clock is therefore the guard: `BB_MIN_MS_PER_MOVE` (150 ms, i.e. 6.7 pops/second, well above human click rate even on the mouse hover-select path) × the number of pops must have elapsed since the round row was created, with `BB_TIME_GRACE_MS` (1500 ms) of slack for clock skew. An instant scripted submit fails with `Runda rozegrana za szybko`; a real 60-pop run needs only ~9 s of the minute-plus it actually takes.

Hero `score_bonus` items are worth `effect_value × BB_ITEM_SCORE_PER_POINT` where that constant is **10**, not the 1 used by Tetris — a good Kulki round lands in the 400-900 range, so a raw +5 would be invisible; ×10 makes a +5 item worth 50 points, a real edge that still can't decide a week on its own. Weekly ranking is score descending, then earlier submission; `accuracy` stores the **share of the board cleared** (`popped / 225 × 100`), which is what `SEASON_LIVE_DEFAULT` tiebreaks the live podium on.

The `BB_*` constant block and the `bbIdx`/`bbRng`/`bbInitState`/`bbGroupAt`/`bbGroupPush`/`bbGroupScore`/`bbSettle`/`bbHasMove`/`bbRemaining`/`bbPopAt` transition functions in `games/bubble-breaker.js` and `supabase/functions/bubble-breaker-action/index.ts` must stay byte-for-byte equivalent. Unlike the other harnesses, **`scripts/bb-parity.mjs` does not re-transcribe the sim a third time** — both copies are delimited by `// ── PARITY BLOCK START` / `END` fences and the harness *extracts and evaluates them from the source files*, so the thing under test is the shipped code and the harness itself cannot drift. It runs two checks: a textual one (the two blocks must match once comments are stripped) and a behavioural fuzz (greedy / smallest-group / random tap policies across thousands of seeds, comparing score, popped, pops, best group, cleared, remaining, over). Rendering constants (`BB_CELL`/`BB_HUD_H`/`BB_CS_*`/`BB_MAX_DPR`/`BB_FALL_MS`/`BB_BURST_MS`/`BB_FLOAT_MS`) were deliberately moved **below** the fence during the promotion so a layout tweak never reads as a parity break.

**The panel serves both modes from one node.** `loadSeasonalTab()` shows `#seasonal-game-bubble-breaker` in place during its season (server-issued seed, round row, `submit`), while `selectAllGame()` moves the same node into `#ag-game-slot` for a free arcade run (local `Math.random()` seed, no round row, score client-reported through `record_arcade_score`, still capped at 12000 in `arcade.sql`). `startBubbleBreakerRound` branches on `allGamesMode` and `finishBubbleBreakerRound` on `rt.archiveMode || !rt.roundId`. No new CSS was needed for the seasonal aside — the existing `#ag-game-slot .bj-board-panel { display: none }` / `.bj-prizes { display: none }` / `.bj-layout { grid-template-columns: 1fr }` rules already collapse it in the arcade. **Input is one rule, two behaviours:** a tap on the *currently selected* group pops it, anything else only selects; a mouse selects by hovering so desktop pops on a single click, while a finger has no hover and naturally falls back to the original's tap-to-select / tap-again-to-confirm. Don't "simplify" that into two code paths. Run order: `bubble-breaker.sql`, then re-run `season-award-gating.sql`; `arcade.sql` already whitelists `bubble_breaker` and needs no change (the two paths write to different tables).

„Tetris G6" (internal gameType `tetris`) is the classic falling-block stacker in a **10×20** well (debuts via override on the week starting 2026-07-27). Pieces come from a **7-bag** randomizer. **Scoring is line-only and deliberately small** (2026-07-26 rebalance): `TT_LINE_SCORES[n]` = 1/3/5/8 for 1/2/3/4 lines, **not multiplied by level**, and both drop bonuses are **0** (`TT_SOFT_DROP_POINTS`/`TT_HARD_DROP_POINTS`) — at 2 pts/cell a piece-spamming run out-scored every line cleared, and the old three-digit line scores × level pushed totals into five digits, making a hero `score_bonus` item rounding noise. `TT_ITEM_SCORE_PER_POINT` is **1** (raw `effect_value`, same convention as the other seasonal games), which lands a +5 item at roughly 5-10% of a realistic run — tune that one constant if items should be louder. **Pacing follows the Tetris Guideline**: the level rises every `TT_LINES_PER_LEVEL` (**10**) lines up to `TT_MAX_LEVEL` (**15**) and gravity speeds up with it (`ttGravityTicks(level) = max(4, 24 - level*1.5)` ticks per row ≈ 1.1s/row at level 1 down to 200 ms at level 15 — **eased 2026-07-31**, was `max(2, 21 - level*2)` ≈ 950 ms down to a much sharper 100 ms floor reached already at level 10; both the slower start and the higher speed floor at the top of the curve were per-office feedback that the late game was near-unreactable, mirrored into `supabase/functions/tetris-action/index.ts` and confirmed by `scripts/tetris-parity.mjs`, 0 mismatches across 600 fuzzed rounds); a grounded piece gets a `TT_LOCK_TICKS` (10 = 0.5 s) lock delay that a move/rotate can refresh up to `TT_MAX_LOCK_RESETS` (12) times. Rotation uses simple horizontal wall kicks (`TT_KICKS = [0,-1,1,-2,2]`, first fit wins) — not full SRS. **The round ends on a top-out** (a spawn that collides); `TT_MAX_TICKS` (12000 = 10 min) is only a safety cap on replay cost, not a game timer. ⚠️ A fixed **60 s** round (`TT_MAX_TICKS` 1200, levels every 4 lines, `max(2, 13 - level)` gravity) was shipped and reverted the same day — it turned the game into a hard-drop sprint with no room for the stack to develop. Don't re-introduce a short hard timer; the difficulty curve is the timer. Like Snake/Invoice Horde/Łap Jajka/Zamknij Popupy it is a **deterministic integer simulation on a 50 ms tick** (seeded LCG driving the bag shuffle) — the browser logs only `{tick, a}` action codes (`0` left, `1` right, `2` rotate CW, `3` rotate CCW, `4` soft drop, `5` hard drop) and `tetris-action` replays `seed + events` to derive the trusted score. Anti-cheat ceilings: `TT_MAX_SCORE` 9999, `TT_MAX_EVENTS` 12000, `TT_MAX_ACTIONS_PER_TICK` 6, and `elapsedTicks` capped against wall-clock elapsed +1.5 s. Hero `score_bonus` items apply as `effect_value × TT_ITEM_SCORE_PER_POINT` (**1**) points; the cross-game `getStrongestHeroEffect` list in that function includes `tetris`. The `TT_*` constant block, the `TT_PIECES` 4×4 rotation bitmask table, and the `ttInitState`/`ttRng`/`ttDrawPiece`/`ttCollides`/`ttSpawn`/`ttLockPiece`/`ttTryMove`/`ttTryRotate`/`ttGrounded`/`ttTouchLock`/`ttApplyAction`/`ttAdvanceTick` transition functions in `games/tetris.js` and `supabase/functions/tetris-action/index.ts` must stay byte-for-byte equivalent (rendering-only constants — `TT_CELL`/`TT_CS_*`/`TT_COLORS`/`TT_DAS_MS`/`TT_ARR_MS`/`TT_MAX_CATCHUP_TICKS` — are client-only); `scripts/tetris-parity.mjs` fuzzes both transcribed copies against several driver policies (including a Dellacherie-lite stacking bot that actually clears lines) and also sanity-checks the piece table (4 connected cells per rotation, in-bounds at the spawn column). Rendering is canvas (`tetrisDraw`): beveled blocks, a ghost-drop outline, a grid, and a side rail carrying the **whole HUD on the canvas** — gold WYNIK, a CZAS clock (`ttClockLabel`/`ttClockColor`, elapsed `m:ss` counting **up**, since the round ends on a top-out; it only turns amber/red in the last 60/30 s of the safety cap), the NEXT preview, POZIOM and LINIE. The DOM `.bj-stats` row mirrors Wynik/Czas/Linie/Poziom, and fullscreen hides its `#tt-stat-level` tile since the rail already prints it. The client tick loop is **self-correcting but never banks a backlog** — more than `TT_MAX_CATCHUP_TICKS` (4) behind resyncs, so a backgrounded tab resumes in slow motion instead of firing a burst of unwatched gravity ticks (this can only make the round run slower than real time, which the server's wall-clock cap already allows). **On handheld the round always opens fullscreen** (`tetrisIsHandheld()` mirrors the `@media (min-width: 780px) and (hover: hover)` query that hides `.tt-pad`): `tetrisEnterFullscreen()` is called **synchronously in the click handler, before the first await**, because `requestFullscreen()` needs a live user gesture — and the `.tt-fs` CSS class, not the native API, is what actually drives the layout, so iOS Safari (no element Fullscreen API) behaves identically. `stopTetrisRound()` drops fullscreen unless called with `{ keepFullscreen: true }` (the begin→stop→begin reset inside `beginTetrisRound`). Weekly ranking uses score descending, then earlier submission (`accuracy` stores cleared lines per piece). Run order: `tetris.sql`, then re-run `season-award-gating.sql` **and** `arcade.sql` (tetris added to the allowed arcade game types, score cap **9999** after the rebalance — `record_arcade_score` is client-callable, so that cap is the only guard on the free-arcade path).
