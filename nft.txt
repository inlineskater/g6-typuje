Lootboxes + NFT collectibles + secondary market

 Context

 The app needs "items that have value." The user wants to sell lootboxes that mint NFTs, where those NFTs then hold/accrue value through scarcity,
 provenance, and price discovery (user-selected: serial rarity premium, provenance history, price history/floor).

 The codebase is already 80% of the way there and no blockchain is needed — we reuse two existing engines instead of inventing new ones:

 - hero_item_instances / hero_item_defs (supabase/hero-items.sql) are already unique serialized tokens: each instance has owner_id, serial_no,
 edition_size, acquired_from. Editions are capped. This is an NFT minus the chain.
 - The Marketplace ("Targowisko") (supabase/marketplace.sql) is already a complete P2P auction/escrow/buy engine where coins transfer buyer→seller. It
 only lacks a link to item instances.

 The gap to close, in three parts:
 1. Lootboxes — a coin-burning RPC that randomly mints a serialized hero-item instance (rarity-weighted, edition-capped).
 2. Secondary market — let players list/sell/auction the instances they own (currently the marketplace only trades free-text listings; minted hero
 items can't be resold P2P).
 3. Value surfacing — serial rarity premium, provenance chain, and per-item price history/floor.

 Coin model: lootbox = burn (mirrors purchase_hero_item); resale = transfer (mirrors marketplace).

 ---
 Part A — Lootboxes (mint NFTs)

 SQL — new file supabase/lootboxes.sql (idempotent)

 Tables:
 - lootbox_defs(id uuid pk, slug text unique, name text, emoji text default '🎁', price integer >0, description text, is_active boolean default true,
 created_at) — the box catalog (e.g. „Skrzynka Brązowa" 50, „Srebrna" 200, „Złota" 1000).
 - lootbox_pool(box_def_id uuid -> lootbox_defs, item_def_id uuid -> hero_item_defs, weight integer >0 default 1, pk(box_def_id, item_def_id)) — which
 hero-item defs each box can drop and their draw weights. (Higher-tier boxes weight rare/epic/legendary more.)
 - lootbox_openings(id uuid pk, user_id uuid -> profiles, box_def_id uuid, item_instance_id uuid -> hero_item_instances, price_paid integer,
 created_at) — history / reveal feed.

 RPC open_lootbox(p_box_slug text) RETURNS json — SECURITY DEFINER SET search_path = public, REVOKE ALL ... ; GRANT EXECUTE TO authenticated (mirror
 place_pixel grant block). Flow:
 1. auth.uid() → not_authenticated; load box def (is_active), box_not_found.
 2. SELECT coins ... FOR UPDATE on profile; insufficient_coins; UPDATE profiles SET coins = coins - price.
 3. Build eligible pool: pool rows whose def is active AND not sold out (edition_size IS NULL OR (count of existing instances) < edition_size). If
 empty → raise pool_empty (and refund — though config should prevent this).
 4. Weighted random pick using random() over cumulative weight (standard ORDER BY -ln(random())/weight LIMIT 1, or cumulative-sum scan).
 5. Assign serial atomically: SELECT ... FROM hero_item_defs WHERE id = chosen FOR UPDATE (serializes concurrent draws of the same def), then
 serial_no = count(instances of that def) + 1. Re-check cap; if exceeded, re-roll within the eligible pool (loop, bounded).
 6. Insert hero_item_instances(item_def_id, owner_id, acquired_from='lootbox', origin_label, serial_no, edition_size).
 7. Append a provenance mint row (Part C).
 8. Ledger: insert coin_transactions reason 'lootbox_open', plus a row in lootbox_openings.
 9. Return { coins, item: { def fields, instance_id, serial_no, edition_size, rarity } } for the client reveal.

 Realtime: ALTER PUBLICATION supabase_realtime ADD TABLE lootbox_openings (guarded) for a live "drops" feed (optional).

 ▎ Reuses existing hero_item_instances shape, so minted NFTs are immediately equippable with their effect_* and visual_effect, show in
 ▎ my_hero_inventory, render on the Tavern avatar via buildHeroSVG, and roll into leaderboard.net_worth through user_assets_value() — zero extra
 ▎ wiring for ownership/display.

 Notes / decisions baked in

 - Lootbox draw uses a SECURITY DEFINER RPC with random() (not an Edge Function) — the result isn't client-replayable, so no anti-cheat function is
 needed; this mirrors purchase_hero_item/place_pixel.
 - Sold-out editions are excluded from the pool (clean) rather than allowing dupes/refunds.
 - Lootbox NFTs are full hero items (equippable, with effects/visuals) — giving them utility value on top of collectible value.
